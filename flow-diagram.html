01 · SIGN IN

Steam OpenID

Every page starts with getSession(): no valid JWT cookie → redirect to /login. Steam verifies you, /auth/steam/callback re-verifies the OpenID signature, pulls your persona via GetPlayerSummaries, upserts the users row, and signs a 30-day JWT (jose, HS256) into an httpOnly cookie before redirecting home. Signing out: POST /auth/logout → clearSession() → /login.

02 · DATA PIPELINE

getLibrarySnapshot() — one deep module

Thin projections (getDashboardData, getGamesData, getAchievementsData, …) all funnel into getLibrarySnapshot, deduped per request by react cache(). It serves the enriched library from a 15-minute DB-backed snapshot (library_snapshots); a miss fans out to Steam in batches of five, and a Steam outage falls back to serving stale data.

03 · PAGE SURFACE

Routes → projections → views

Every route is force-dynamic and session-gated; unauthenticated visits bounce to /login. Each page calls exactly one thin projection over the shared library snapshot — except the per-game page, which queries Steam live.

04 · MUTATIONS

Browser → API routes → DB

Writes never touch Steam — they land straight in Turso and take effect on the next render, because tracking flags are re-applied onto the cached library on every request.

POST/api/tracked-games
body {appId} → INSERT INTO tracked_games (onConflictDoNothing)
DELETE/api/tracked-games?appId=…
removes the (steamId, appId) row → game flips untracked
PUT/api/settings
body {defaultFilter} → upsert user_preferences; validated against all·owned·tracked
GET/api/dashboard?filter=…
JSON projection of getDashboardData() — same deep module as SSR
POST/auth/logout
clearSession() zeroes the cookie → redirect /login
05 · NIGHTLY

Snapshot cron

A daily cron authenticates with a bearer secret, walks every user, and pins a snapshots row (earned, avg completion ×10, owned). Those historical rows are what let the dashboard show real Δ deltas instead of frozen nulls.
